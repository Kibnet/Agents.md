# Governance: SPEC Rubric

## Когда применять

- Для оценки готовности short/expanded SPEC к автономной реализации после approval.

## MUST

- Оценить шесть критериев по шкале 0/2/5 и записать обоснования в SPEC: цель/границы; AS-IS; конкретность дизайна; безопасность/миграция/rollback; проверяемость; автономность решений.
- Сумма 0–10 — рискованно, 11–20 — под контролем, 21–30 — готово к автономной реализации. Порог 21 — ориентир, не замена exact approval и critical gates.
- При FAIL критичного linter блока или незакрытом HIGH/MEDIUM review не выдавать готовность по одной сумме.

## Примеры шкалы

| Балл | Пример критерия «проверяемость» | Пример критерия «безопасность» |
| --- | --- | --- |
| 0 | Нет наблюдаемого AC/проверки | Данные меняются, миграция/rollback отсутствуют |
| 2 | Happy path проверяется, failure/recovery не определён | Backup назван, восстановление и drift не определены |
| 5 | AC связан с командой/fixture/evidence, негативный случай определён | Область данных, совместимость и проверяемый rollback заданы; либо неприменимость объяснена |

Полнота означает достаточность для риска задачи, а не длину текста. Для остальных критериев 0 — отсутствует/непроверяемо; 2 — частично с конкретной неопределённостью; 5 — ясно, полно и проверяемо.
