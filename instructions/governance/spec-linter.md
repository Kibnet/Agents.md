# Governance: SPEC Linter

## Когда применять

- Перед approval новой SPEC и при review качества спецификации.

## MUST

- Оценить каждый критерий 1..20 как PASS/PARTIAL/FAIL с коротким проверяемым пояснением. Оцениваются сведения, а не число заголовков: short SPEC может объединять строки.
- Неприменимость сопровождать причиной; отсутствие критичного сведения не маскировать `Не применимо`.
- Итог ГОТОВО допускается без FAIL в A/C/D. НУЖНА ДОРАБОТКА — при любом FAIL A/C/D. Нерешённый HIGH/MEDIUM из review блокирует approval независимо от баллов; применяются дополнительные gates review owner.
- Сохранить результат в рабочей SPEC. Для PARTIAL указать конкретный остаточный риск и действие.

## Критерии

| № | Блок | Что проверяется |
| --- | --- | --- |
| 1 | A | Цель и наблюдаемый outcome |
| 2 | A | Проверенный AS-IS |
| 3 | A | Корневая проблема |
| 4 | A | Цели дизайна |
| 5 | A | Границы / Non-Goals |
| 6 | B | Ответственности |
| 7 | B | Точки интеграции |
| 8 | B | Алгоритмы и инварианты |
| 9 | B | Ошибки и recovery |
| 10 | B | Performance либо обоснованная неприменимость |
| 11 | C | Данные / состояние |
| 12 | C | Совместимость и миграция |
| 13 | C | Rollback |
| 14 | D | Измеримые AC |
| 15 | D | AC→test/evidence, включая негативные случаи |
| 16 | D | Команды и stop rules |
| 17 | E | План и зависимости |
| 18 | E | Решения и открытые вопросы |
| 19 | E | Масштаб и выбранная форма |
| 20 | F | Соответствие применимому profile |
