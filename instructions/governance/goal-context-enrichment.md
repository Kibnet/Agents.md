# Governance: Goal Context Enrichment

## Когда применять

- Проверенный факт или принятое решение по задаче полезно для следующего шага её смыслового родителя.

## Когда не применять

- Нет полезного для родителя нового факта/решения либо нужно просто продублировать лог.
- Выполненность ребёнка сама по себе не является достигнутостью цели.

## MUST

- По всем parent chains из task-context выбирать ближайшего смыслового родителя, а не случайный root. При нескольких подходящих ветвях назвать точные parent IDs и обоснование; неизвестную ветвь не объявлять просмотренной.
- Готовить компактный текст: «Факт/решение; источник/дата; значение для следующего шага; ссылка на компактный результат». Hypothesis помечать отдельно, проверки/limits сохранять. Не копировать секреты, личный профиль и полные логи.
- Предложение и применение различать. Child authority не распространяется на parent; description родителя не расширяется без конкретного разрешения на это поле/ID. Без него сохранить proposal в разрешённом artifact и zero tracker writes.
- При разрешённом применении использовать mutation/readback contract result-tracking, сохраняя существующее описание и защищённые поля. Не архивировать/завершать родителя по результату ребёнка.

## SHOULD

- Сохранять provenance и ссылку на подробное evidence вместо дублирования результата; выбирать факт, который изменяет следующее действие человека/агента.
